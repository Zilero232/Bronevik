# In-game replay managers (2026-09-30)

What the modpacks ship for replays in the hangar, how a replay is started from a running client, and what our `replay_manager` does about it.

## Who ships what

| Product | Replay manager | Notes |
| --- | --- | --- |
| POLIROID Replays Manager (MIT, `refs/mods/poliroid__replays-manager`, v3.9.0) | Yes | The one every big pack bundles: Jove, Lebwa, Near_You, Aslain. Scaleform window, 10 rows a page, a Filter/Info side panel, row context menu. |
| MTReplays fork (mtreplays.ru) | Yes | POLIROID's mod pointed at the mtreplays.ru upload API for Lesta 1.42–1.45. Same UI, same restart to play. |
| Lesta Replays (lesta-replays.ru) | No list | OpenWG.Gameface mod that uploads every replay. |
| Battle Observer, wotstat | No | Only check `BattleReplay.isPlaying()` to switch their HUD off during a replay. |
| XVM | No | — |

POLIROID's list, per row: map, vehicle icon and name, result, damage, assist (radio+track+stun), spotted, frags, XP, credits, date, battle type. No map picture, no duration, no mastery. Filters: date (today/week/month), map, nation, class, tier, battle type, result, favourites, an «original XP» toggle; sort on any column; no text search. Actions: native results window, play, upload (title, description, hidden flag), favourite, delete with a dialog. No rename, no «open folder». Metadata cache in a `shelve` DB keyed by mtime, parsed one file per `BigWorld.callback(0)`. Its version gate is a minimum of 2.2.0.0 (WG numbering), so on Lesta 1.45 it marks every replay as unsupported as shipped.

## Playing a replay: the client (RU 1.45 sources)

- `BattleReplay.g_replayCtrl.play(fileName)` (`BattleReplay.py:363`) starts playback, but nothing in the client calls it except `autoStartBattleReplay()` (`:458`), which runs only from `gameplay.machine.BattleReplayMachine.start()`. The machine is picked once at start-up (`gameplay/machine.py:44`: a replay path on the command line or a Windows file association → `BattleReplayMachine`). There is no «play» from a logged-in hangar.
- `stop()` (`:403`) disconnects and, for a replay started at launch (`__quitAfterStop`), calls `BigWorld.quit()`. Leaving through Esc and «Закончить» in the end dialog both end there.
- Version: the engine compares `BigWorld.getProductVersion()` with the header's `clientVersionFromExe`; a mismatch shows the client's `replayNotification` dialog (it asks, it does not refuse), and «no» stops a replay that never started.
- POLIROID's way: write a flag file, `BigWorld.restartGame()`, and on the next start (mods load in `gui_personality.init`, before `ServiceLocator.gameplay.start()`) swap `GameplayLogic.__machine` for a `BattleReplayMachine` and override `getAutoStartFileName`. It leaves the Esc path quitting the client.

## Header data

Block 1 (always): `playerID`, `playerName`, `playerVehicle` (`nation-Name`), `mapName`, `mapDisplayName`, `dateTime`, `arenaUniqueID`, `battleType` (`ARENA_BONUS_TYPE`), `gameplayID`, `clientVersionFromExe`, `serverName`, plus a `vehicles` block of everybody in the battle (never read by us). No tier: it comes from `items.vehicles`. Block 2 (only when the battle was watched to its end): `[results, vehiclesInfo, statistics]`; we read `results.personal[<own vehicle>]` and `results.common` only. Client images: `gui/maps/icons/map/stats/<mapName>.png` (500×235), `map/small/<mapName>.png` (100×60), `vehicle/<playerVehicle>.png` (160×100), `library/proficiency/class_icons_<n>_small.png`.

## What we did (replay_manager 0.3.0)

- A replays screen in the settings window (the component's page, `kind: "replays"`): every own replay with the map picture, hangar vehicle icon, tier, type, result stripe, damage/assist/frags, site state, favourite; a details pane with the result, stats tiles, mastery, survival and the actions. Virtualised list (1000 files), instant client-side search, filters (result, map, vehicle, tier, battle type, period, favourites), sort on date/damage/assist/XP/frags/duration/size both ways, and a summary of the selection (win rate, averages) no competitor has.
- «Смотреть» follows POLIROID's restart, with three differences: only replays of the exact running version can be started (no dead-end dialog), a stale request (over 3 minutes) is dropped so a crash never replays on its own, and both exits (Esc and «Закончить») restart the client instead of quitting.
- Upload through `replay_upload` (the same opt-in switch and binding), rename, delete with a confirmation, open the folder. Headers are cached on disk and new files are read in 150 ms slices of the hangar tick.
- Fair play: only the recorder's own files (`playerID` = the logged-in account) and its own `personal` entry; the `vehicles`, `players` and `avatars` blocks are never read.

Not done yet: the native battle-results window for a replay (POLIROID rebuilds the nulled `*Replay` fields and patches the results service), and bulk delete / clean-up rules.
